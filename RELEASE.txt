FRECUENCIA CERO V19 — CORRECCIÓN DE CONFIRMACIÓN DEL ENLACE ALTERNATIVO

CAMBIOS
- Corregido el inicio de la transacción de reclamación de invitaciones. En determinados navegadores el SDK podía invocar el callback de la transacción con estado local null aunque la lectura previa ya hubiera devuelto la invitación pendiente; el callback abortaba localmente y mostraba “Firebase no pudo confirmar la invitación”.
- La transacción usa la lectura reciente como respaldo solo en su primer estado local vacío. Firebase sigue verificando el hash y reejecuta el callback con el estado real del servidor cuando hay discrepancia.
- Se añade un único reintento después de releer el token si continúa pendiente. El uso único sigue protegido por la transacción y por las reglas de Realtime Database.
- Se mejora el mensaje de error para distinguir rechazo de reglas, vencimiento, token reclamado y fallo transaccional.
- No se cambian UID, banda, miembros, dispositivos, catálogo, eventos ni reglas Firebase V17.

INSTALACIÓN
1. Sube todos los archivos de este paquete a la raíz del repositorio GitHub Pages, sustituyendo V18.
2. Publica el commit en la rama main.
3. En cada dispositivo utiliza Más → Buscar actualizaciones.
4. No es necesario volver a publicar reglas Firebase para esta corrección. Conserva las reglas V17 que ya publicaste.
5. No borres los datos de Safari ni elimines el acceso de la pantalla de inicio.

PRUEBA
1. Genera una invitación nueva (QR/enlace) desde el dispositivo autorizado.
2. Abre el enlace en un navegador que no esté vinculado.
3. Pulsa “Vincular este dispositivo”.
4. Comprueba que el dispositivo aparezca en “Mis dispositivos vinculados”.
5. Comprueba que el enlace quede inutilizable después de la vinculación.

NOTA
QR y enlace alternativo comparten el mismo token de un solo uso con vigencia de 3 minutos. Esta versión debe probarse contra el proyecto Firebase real; el paquete no publica cambios en Firebase ni puede probar la conexión remota desde este entorno.
